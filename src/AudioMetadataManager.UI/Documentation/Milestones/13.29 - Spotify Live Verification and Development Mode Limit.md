# Milestone 13.29

## Verificación real de Spotify y el límite real de "Development mode"

## Objetivo

Verificar el proveedor Spotify (milestone 13.28) contra la API real,
con credenciales reales, ahora que el usuario creó la app
("searchdatos") en el panel de desarrolladores de Spotify.

## Hallazgo: el límite documentado de 50 no aplica a apps nuevas

Con las credenciales configuradas, la primera búsqueda real falló:

```
HTTP 400
{"error": {"status": 400, "message": "Invalid limit"}}
```

La causa no era un error de codificación de URL (se descartó
explícitamente: se comparó `Uri.ToString()` —que "decodifica" espacios
para mostrarse de forma legible— contra `Uri.AbsoluteUri` y
`Uri.PathAndQuery` —el formato real que efectivamente viaja por la
red— y ambos coincidían, correctamente codificados, sin importar si la
URL se construía con `UriBuilder.Query` o por concatenación manual).

Se aisló el problema variando el parámetro `limit` en solicitudes
directas a la API real, sin pasar por ninguna abstracción del
proyecto:

- `limit` entre 1 y 10: `200 OK`.
- `limit` de 11 en adelante (probado hasta 50): siempre
  `400 Invalid limit`.

La documentación pública de Spotify indica un rango válido de 1 a 50.
En la práctica, una app recién creada en **"Development mode"**
(visible en el dashboard de Spotify como el estado de la app) queda
limitada a `limit <= 10` en el endpoint de búsqueda. No es un límite
documentado; se descubrió empíricamente.

## Corrección

`SpotifyOptions.ResultsPerPage` cambió su valor predeterminado de `20`
a `10`, con un comentario que explica el hallazgo y cómo debería
revisarse si la app de Spotify sale de modo desarrollo (Extended Quota
Mode). El rango de validación (`IsValid`, 1-50) no se tocó, ya que
sigue siendo el rango documentado oficialmente; sólo cambió el valor
por defecto para que la aplicación funcione sin configuración
adicional en el caso común (una app recién creada).

## Verificación

Con el valor corregido, se repitió la búsqueda real
(`SpotifyMetadataProvider.SearchAsync`, con las credenciales guardadas
en el Administrador de credenciales de Windows vía
`SpotifyCredentialStore.SaveCredentials`) para "Daft Punk" /
"One More Time":

- `Status: Success`, `HttpStatusCode: 200`.
- 8 candidatos utilizables, todos correctamente mapeados: artista,
  título, álbum, fecha de lanzamiento, duración, carátula (URL de
  imagen real de Spotify) y dirección pública de la pista.
- El primer resultado fue exactamente la pista buscada: "Daft Punk -
  One More Time", álbum "Discovery" (2001-03-12).

Esto confirma el camino completo en producción: credenciales
guardadas → `SpotifyOptionsFactory` las lee → `SpotifyAuthClient`
intercambia y cachea un token real → `SpotifySearchExecutor` ejecuta
la búsqueda real → el parser y el mapeador procesan la respuesta real
→ candidatos utilizables por el resto de la aplicación.
