Objetivo

Incorporar un CHANGELOG centralizado para registrar de forma clara
la evolución funcional y técnica de Audio Metadata Manager.

Decisión

Se utilizará un único archivo CHANGELOG.md ubicado en la raíz del
repositorio.

Estructura

El documento utilizará las secciones:

- Added
- Changed
- Fixed
- Internal

Cada milestone aportará un bloque preparado para insertar dentro de
la sección Unreleased.

Flujo futuro

Antes de realizar cada commit de milestone:

1. Se actualizará CHANGELOG.md.
2. Se guardará el archivo.
3. GitHub Desktop mostrará el código y el changelog como parte del
   mismo conjunto de cambios.
4. Ambos se incluirán en el mismo commit.

Resultado

La evolución del proyecto quedará documentada junto con cada cambio
funcional, sin requerir herramientas adicionales.
