# Milestone 13.37 - Manual Metadata Override

## Objetivo

Permitir que el usuario introduzca un valor de metadatos verificable cuando
las fuentes externas no aportan evidencia suficiente, sin convertir la falta
de evidencia en una aprobación automática ni omitir las protecciones del
flujo productivo.

## Alcance

La vista de simulación incorpora una acción `Ingresar valor` para los campos
que ya tienen soporte productivo seguro:

- artista;
- título;
- versión;
- álbum / lanzamiento;
- sello;
- género.

Los campos rechazados por una regla técnica y los campos sin soporte de
escritura continúan sin aceptar una sustitución manual.

## Flujo de usuario

1. El usuario abre `Ingresar valor` en una propuesta.
2. La aplicación muestra el campo y el valor almacenado actualmente.
3. El usuario introduce un valor no vacío.
4. La fila pasa a `Valor manual pendiente` y registra `Usuario` como origen.
5. El archivo todavía no se modifica.
6. El usuario debe marcar `Aplicar` para aprobar explícitamente el valor.
7. El cambio entra en el flujo productivo existente de preparación aislada,
   respaldo, escritura, verificación, segunda confirmación y promoción.

## Reglas de seguridad

- Un valor manual nunca queda seleccionado automáticamente.
- Un texto vacío se rechaza.
- Un valor igual al metadato actual no se considera cambio.
- La confianza externa se muestra como `Manual`; no se inventa un porcentaje.
- La procedencia enviada al pipeline se registra como `Usuario`.
- Una decisión técnica `Rejected` no puede anularse desde la interfaz.
- Las políticas de soporte productivo siguen siendo la autoridad para decidir
  qué campos pueden escribirse.
- `Validar cambios aprobados` ejecuta únicamente comprobaciones estructurales
  y preparación en memoria; no crea respaldos ni invoca el pipeline de
  escritura.

## Cambios técnicos

`SimulationProposalViewModel` distingue ahora entre la propuesta técnica y el
valor efectivo. Una sustitución manual recalcula la existencia de un cambio,
la capacidad de selección, el estado de revisión, la procedencia y el texto de
decisión visible.

`MetadataApplyRequestFactory` utiliza el valor efectivo aprobado y conserva la
auditoría manual en `MetadataFieldChange`.

Durante la validación manual se detectó que el botón de validación conservaba
una integración histórica con `MetadataApplicationPipeline`. Como el pipeline
ya utiliza writers reales, esa ruta podía guardar el metadato antes de la
preparación productiva aunque el mensaje afirmara lo contrario. La integración
fue eliminada: la acción usa ahora `MetadataApplyRequestValidator` y la
preparación TagLibSharp sin `Save()`.

También se restauró la actualización posterior del flujo batch. Después de
una promoción correcta, cada fila promovida se vuelve a leer desde disco y el
archivo actualmente seleccionado reconstruye automáticamente su plan. El
análisis solicitado manualmente también refresca primero las etiquetas para no
trabajar con el modelo creado durante un escaneo anterior.

La vista de simulación incorpora `ManualMetadataValueDialog`, que captura el
valor sin escribir directamente sobre el archivo.

La tabla también fue compactada para conservar visibles las columnas de
decisión en el ancho predeterminado. El valor efectivo y la acción manual
comparten ahora una sola columna, mientras `Aplicar` y `Campo` permanecen
inmovilizadas durante el desplazamiento horizontal. Los avisos inferiores
distinguen la edición segura de propuestas del flujo productivo, que siempre
requiere preparación y confirmación.

La navegación de detalles separa ahora `Metadatos` y `Renombrado`. La primera
pestaña contiene las propuestas de etiquetas y su flujo productivo. La segunda
muestra el nombre actual, el nombre propuesto y el estado de confianza como una
vista previa independiente. El renombrado productivo permanece deshabilitado
hasta incorporar validación de nombres, detección de colisiones, respaldo y
una confirmación específica para esa operación.

Después de la validación visual, estas áreas dejaron de mostrarse como pestañas
internas del panel estrecho de detalles. `Biblioteca`, `Información`,
`Metadatos`, `Renombrado`, `Duplicados` y `Actividad` son ahora pestañas
principales del espacio de trabajo. Todas conservan la misma selección de
archivo, mientras cada flujo dispone del ancho y alto centrales de la ventana.

## Pruebas automatizadas

Se agregó cobertura para comprobar que:

- una propuesta con evidencia insuficiente se vuelve seleccionable después de
  recibir un valor manual válido;
- el cambio productivo conserva el nuevo valor y la procedencia `Usuario`;
- un valor igual al actual no puede seleccionarse;
- los valores vacíos son rechazados.
- la preparación MP3 previa acepta `Version` y `Label` mediante el mismo mapper
  central utilizado por el escritor productivo;
- esa preparación extendida no ejecuta `Save()` y conserva el hash físico del
  archivo.

Al finalizar el milestone:

- se ejecutan 115 pruebas automatizadas;
- 115 pruebas finalizan correctamente;
- no existen pruebas fallidas;
- la solución y la nueva ventana WPF compilan correctamente.

## Resultado

La falta de evidencia externa ya no bloquea por completo una corrección que el
usuario conoce. La aplicación mantiene una separación explícita entre
evidencia automática y decisión humana, y aplica ambas mediante el mismo flujo
productivo protegido y auditable.
