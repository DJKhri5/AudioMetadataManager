# Milestone 13.36 - Productive Metadata Field Expansion

## Objetivo

Ampliar de forma segura la aplicación productiva de metadatos para incorporar
los campos `Version` y `Label`, manteniendo las garantías existentes de
preparación aislada, verificación posterior, promoción explícita y rollback.

El milestone también busca asegurar que los valores persistidos puedan volver
a leerse después de la promoción y que el motor de decisiones no proponga de
nuevo un cambio que ya está almacenado en el archivo.

## Alcance

Los nuevos campos productivos son:

- `Version`, almacenado como `TagLib.Tag.Subtitle` y como frame ID3v2 `TIT3`
  en archivos MP3;
- `Label`, almacenado como `TagLib.Tag.Publisher` y como frame ID3v2 `TPUB`
  en archivos MP3.

La política centralizada `MetadataProductiveFieldSupport` reconoce ahora ambos
campos. Esto permite que participen en solicitudes productivas, selecciones de
lote, escritura, verificación y actualización posterior de la interfaz.

## Escritura productiva de Label

La escritura genérica mediante `TagLib.Tag.Publisher` no modificaba físicamente
el MP3 utilizado durante la validación productiva. El mapper necesitaba acceso
al objeto `TagLib.File` completo para obtener o crear explícitamente la etiqueta
ID3v2 y administrar el frame `TPUB`.

Se agregó una sobrecarga de `PrepareChange` que recibe `TagLib.File`. El writer
común utiliza esa sobrecarga durante la preparación de campos. Para archivos
MP3 y cambios de `Label`, el mapper:

1. obtiene o crea la etiqueta ID3v2;
2. obtiene o crea el frame `TPUB`;
3. conserva el valor original;
4. asigna el valor solicitado;
5. vuelve a leer el frame en memoria;
6. produce un resultado auditable.

Los demás campos y formatos continúan utilizando la ruta genérica de
`TagLib.Tag`, evitando introducir una etiqueta ID3v2 en formatos que no la
requieren.

## Escritura productiva de Version

`Version` utiliza la propiedad nativa `TagLib.Tag.Subtitle`. En archivos MP3,
TagLibSharp la persiste mediante el frame ID3v2 `TIT3`.

La prueba controlada del milestone confirmó que:

- el archivo temporal cambia físicamente después de `Save()`;
- `TIT3` conserva `Extended Mix` después de cerrar y reabrir el MP3;
- `TagLib.Tag.Subtitle` devuelve el mismo valor persistido;
- el lector local incorpora la versión al modelo de la aplicación;
- el motor de decisiones prioriza la versión explícita almacenada y conserva
  la interpretación desde el título como compatibilidad.

Esta validación no depende de que Discogs u otra fuente externa proporcione
una versión utilizable.

## Lectura local y reconstrucción del plan

`AudioFile` incorpora propiedades explícitas para `Version` y `Label`.
`MetadataReaderService` las obtiene desde `Subtitle` y `Publisher` al analizar
el archivo.

También se actualizaron:

- `LocalMetadataComparisonInputFactory`;
- `AudioFileMetadataComparisonAdapter`;
- `MetadataChangeDecisionEngine`.

Con esta integración, los valores persistidos participan de forma coherente en
el ranking local, las comparaciones, la confianza y el plan de modificaciones.

Durante la validación manual se detectó que el ranking ya reconocía
`Label = Chrome Red`, pero el plan todavía forzaba el valor actual a vacío. Esto
provocaba una propuesta duplicada y un intento de escritura que no cambiaba el
hash porque el archivo ya contenía el valor solicitado. La lectura de
`MetadataChangeDecisionEngine` fue corregida para utilizar `AudioFile.Label`.

## Evidencia insuficiente

Cuando ninguna fuente externa entrega una versión utilizable, la decisión
`InsufficientEvidence` continúa siendo el resultado esperado. El sistema no
inventa un valor, no crea un cambio real y no habilita una aplicación
productiva basada en evidencia inexistente.

La capacidad técnica de persistir `Version` se valida mediante una prueba
controlada independiente de las fuentes externas. La incorporación futura de
edición manual de valores sería una funcionalidad separada y no modifica esta
regla de seguridad.

## Pruebas automatizadas

Se amplió la cobertura para comprobar:

- soporte productivo de `Version` y `Label`;
- round-trip en memoria de `Subtitle` y `Publisher`;
- persistencia física de `TPUB` sobre un MP3 temporal;
- cambio de hash después de guardar `Label`;
- reapertura y lectura de `Chrome Red` desde `TPUB`;
- lectura de `Label` mediante `MetadataReaderService`;
- persistencia física de `TIT3` sobre un MP3 temporal;
- cambio de hash después de guardar `Version`;
- reapertura y lectura de `Extended Mix` desde `TIT3`;
- lectura de `Version` mediante `MetadataReaderService`;
- uso de los valores almacenados por el motor de decisiones.

Al finalizar el milestone:

- se ejecutan 109 pruebas automatizadas;
- 109 pruebas finalizan correctamente;
- no existen pruebas fallidas;
- la solución compila correctamente.

## Validación manual

La ruta productiva de `Label` fue validada con una copia MP3 real:

1. Discogs propuso `Chrome Red`;
2. el cambio fue aprobado manualmente;
3. el lote completó preparación y promoción;
4. el MP3 conservó `TPUB = Chrome Red`;
5. el análisis posterior recuperó el sello;
6. el plan reconstruido mostró `Chrome Red` como valor actual y propuesto;
7. la decisión final fue `NoChangesRequired`.

La ruta de `Version` fue validada mediante un MP3 temporal controlado, ya que
los archivos disponibles no recibían una versión utilizable desde las fuentes
externas.

## Seguridad

El milestone conserva las garantías productivas existentes:

- las pruebas de persistencia utilizan archivos temporales;
- la biblioteca original no se modifica durante las pruebas automatizadas;
- una preparación sin cambios físicos no se conserva como promovible;
- los valores sin evidencia suficiente no se aplican;
- la promoción real continúa requiriendo confirmación explícita;
- la verificación, backup, rollback y limpieza permanecen a cargo de la
  infraestructura productiva existente.

## Resultado

`Version` y `Label` disponen ahora de una ruta productiva completa que incluye
soporte, preparación, escritura, persistencia física, verificación, lectura y
reconstrucción correcta del plan.

La aplicación distingue además entre falta de evidencia externa y falta de
capacidad técnica de escritura. Esto permite mantener decisiones seguras sin
impedir que la persistencia de `TIT3` y `TPUB` sea validada de forma
determinista.
