# Milestone 13.34 - Productive Batch Workflow

## Objetivo

Completar la capa de workflow productivo por lote utilizada por la interfaz,
separando explícitamente la preparación de los archivos de la decisión final
de promoción.

El objetivo principal de este milestone es evitar que `MainWindow` tenga que
coordinar directamente los detalles internos del coordinador productivo
two-phase y proporcionar una operación de lote reutilizable, validada y
auditable.

## Cambios realizados

### ProductiveBatchWorkflowService

Se agregó una capa de workflow dedicada para la ejecución productiva por lote:

- `IProductiveBatchWorkflowService`
- `ProductiveBatchWorkflowService`
- `ProductiveBatchPreparation`

El workflow expone dos fases claramente separadas:

1. `PrepareAsync`
2. `CompleteAsync`

La fase de preparación:

- valida la solicitud `MetadataApplyBatchRequest`;
- delega la preparación al coordinador productivo two-phase existente;
- mantiene los archivos aislados de los originales;
- devuelve una preparación explícita que puede ser evaluada antes de tomar
  una decisión productiva.

La fase de finalización:

- solamente acepta decisiones `Approved` o `Declined`;
- requiere que la preparación esté realmente lista para una decisión;
- delega la promoción o descarte al coordinador productivo existente;
- conserva la política de seguridad ya implementada para promoción,
  verificación, limpieza y rollback.

## Protección contra reutilización de preparaciones

La preparación productiva representa una operación consumible.

Una preparación que ya fue utilizada para una finalización no puede volver a
ser completada una segunda vez.

Esto evita:

- promociones duplicadas;
- reutilización accidental de copias aisladas;
- ejecución repetida sobre un mismo estado temporal;
- comportamiento ambiguo desde la interfaz.

La validación está cubierta por pruebas automatizadas.

## Integración con MainWindow

La operación productiva por lote de `MainWindow` utiliza ahora el workflow
dedicado.

El flujo de interfaz queda estructurado de la siguiente manera:

1. convertir la selección productiva de la interfaz en
   `MetadataApplyBatchRequest`;
2. preparar el lote;
3. verificar que la preparación esté lista;
4. solicitar una decisión global al usuario;
5. completar el workflow con `Approved` o `Declined`;
6. registrar el resultado y los mensajes de auditoría;
7. limpiar el estado visual cuando la promoción termina correctamente.

La interfaz ya no necesita coordinar directamente las dos fases internas del
coordinador productivo.

## Seguridad

El milestone conserva las reglas de seguridad existentes:

- ningún archivo original se modifica durante la preparación;
- la promoción solamente puede realizarse después de una decisión explícita;
- `Declined` descarta el lote sin modificar los archivos originales;
- decisiones distintas de `Approved` y `Declined` son rechazadas;
- una preparación consumida no puede ejecutarse nuevamente;
- la lógica de backup, verificación, promoción, rollback y limpieza continúa
  delegada a la infraestructura productiva existente.

## Pruebas automatizadas

Se agregó cobertura específica para `ProductiveBatchWorkflowService`.

Entre los escenarios cubiertos se encuentran:

- coordinador nulo rechazado;
- lote nulo rechazado;
- lote estructuralmente inválido rechazado;
- preparación válida preservada;
- decisión `Approved` reenviada correctamente;
- decisiones no soportadas rechazadas;
- preparación consumida correctamente;
- una preparación consumida no puede completarse dos veces.

Al finalizar el milestone:

- la solución compila sin errores;
- se ejecutan 86 pruebas automatizadas;
- 86 pruebas finalizan correctamente;
- no existen pruebas fallidas.

## Resultado

La aplicación dispone ahora de una capa explícita de workflow productivo por
lote entre la interfaz y los coordinadores de bajo nivel.

Esto reduce el acoplamiento de `MainWindow`, protege el ciclo de vida de una
preparación productiva y deja una base más limpia para continuar evolucionando
la experiencia de aplicación por lote.
