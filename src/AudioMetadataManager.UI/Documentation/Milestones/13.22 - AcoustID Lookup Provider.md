# Milestone 13.22

## Proveedor de identificación AcoustID

## Objetivo

Cerrar el flujo de identificación automática de pistas iniciado en el
milestone 13.21: a partir de una huella acústica Chromaprint y su
duración, consultar la API pública de AcoustID y obtener el
identificador de grabación (Recording MBID) de MusicBrainz asociado.

Este milestone incorpora únicamente el cliente de consulta. El
encadenamiento automático `Chromaprint → AcoustID → MetadataSearchRequest`
queda para un milestone posterior.

## Componentes incorporados

Se replicó la misma organización en capas ya utilizada por Discogs
(`Configuration` → `Dtos` → `Api` → `Mapping` → `Execution` → proveedor
de entrada → `Diagnostics`), bajo `Providers/AcoustId/`.

### Configuration

- `AcoustIdOptions`: dirección base, clave de cliente, campos `meta`
  solicitados (`recordings`) y tiempo máximo de solicitud.
- `AcoustIdApiKeyStore`: guarda y recupera la clave de cliente
  mediante el Administrador de credenciales de Windows, reutilizando
  `ISecretStore` de la misma forma que `DiscogsTokenStore`. La clave
  nunca se almacena en el código fuente.
- `AcoustIdOptionsFactory`: construye la configuración predeterminada
  leyendo la clave guardada.

### Dtos

`AcoustIdLookupResponseDto`, `AcoustIdResultDto`, `AcoustIdRecordingDto`,
`AcoustIdArtistDto` y `AcoustIdErrorDto` reflejan la respuesta JSON de
`GET /v2/lookup`.

### Api

- `AcoustIdApiRequestBuilder`: construye la URL de consulta con
  `client`, `fingerprint`, `duration` y `meta`.
- `AcoustIdApiClient`: ejecuta la solicitud HTTP, con manejo de
  timeout y errores de transporte, siguiendo el mismo patrón que
  `DiscogsApiClient`.
- `AcoustIdApiResponse`: respuesta HTTP normalizada.

### Mapping

- `AcoustIdLookupResponseParser`: deserializa el JSON de respuesta.
- `AcoustIdRecordingCandidateMapper`: convierte los resultados en
  `AcoustIdRecordingCandidate`, ordenados de mayor a menor confianza,
  descartando grabaciones sin MBID.

### Models

- `AcoustIdProviderStatus`: estado normalizado de la operación.
- `AcoustIdLookupRequest`: huella y duración de entrada.
- `AcoustIdRecordingCandidate`: grabación normalizada (MBID, título,
  artistas combinados, duración, confianza).
- `AcoustIdLookupResult`: resultado completo, con `BestCandidate`
  (mejor coincidencia según confianza) y factorías estáticas
  `InvalidRequest` / `InvalidConfiguration`.

### Execution

`AcoustIdLookupExecutor` coordina cliente, parser y mapeador.

Particularidad de AcoustID: el servicio normalmente responde HTTP 200
incluso cuando la consulta falla lógicamente, informando el error
dentro del cuerpo JSON (`status: "error"`, con un código y un
mensaje). El ejecutor interpreta ese campo de forma independiente del
código HTTP, y clasifica los códigos de error `4` y `6` (clave de API
inválida) como `AuthenticationFailed`.

### AcoustIdLookupProvider

Punto de entrada público. Valida configuración, datos mínimos de la
solicitud y presencia de la clave de cliente antes de delegar en el
ejecutor, siguiendo el mismo rol que `DiscogsMetadataProvider`.

### Diagnostics

`AcoustIdLookupDiagnostics` ejecuta una identificación controlada dado
un fingerprint y una duración, y construye un informe legible con las
grabaciones encontradas y su confianza.

## Correspondencia de resultados

- Grabaciones encontradas: `Success`.
- Consulta válida sin coincidencias: `NoResults`.
- Huella o duración faltante: `InvalidRequest`.
- Configuración inválida: `InvalidConfiguration`.
- Clave de cliente ausente o rechazada (HTTP 401/403, o código de
  error `4`/`6` en el cuerpo): `AuthenticationFailed`.
- HTTP 429: `RateLimited`.
- Error de transporte o 5xx: `NetworkError`.
- Respuesta JSON no interpretable: `InvalidResponse`.
- Cualquier otro error informado por el cuerpo JSON: `UnexpectedError`.

## Decisión arquitectónica

Al igual que Chromaprint, AcoustID no se registró como
`IMetadataSource`. Su resultado es un identificador de MusicBrainz, no
un candidato de metadatos musical completo; conectar ambos formará
parte de un paso de identificación explícito dentro del pipeline de
búsqueda, no de `MetadataSourceFactory`.

## Verificación

Sin ejecutor de pruebas estructurales, por la misma razón documentada
en el milestone 13.21: los proveedores bajo `MetadataSources/Providers`
no utilizan esa ceremonia.

Tras instalar el SDK de .NET 8 (`8.0.423`) en la máquina de desarrollo,
se ejecutó `dotnet build` sobre `AudioMetadataManager.UI.csproj`
incluyendo este proveedor. La compilación terminó sin errores ni
advertencias; el único defecto detectado en la misma corrida
pertenecía a `ChromaprintFingerprintExecutor` (milestone 13.21), no a
este componente.

No se ejecutó ninguna consulta real contra AcoustID, ya que requiere
una clave de cliente válida que todavía no se ha configurado mediante
`AcoustIdApiKeyStore`.
