# Milestone 13.15

## Ejecutor modular del pipeline de aplicación

## Objetivo

Crear una infraestructura genérica para ejecutar etapas independientes
del pipeline sobre un único `MetadataApplicationContext`.

El ejecutor no debe conocer la implementación interna de validación,
respaldo, escritura o verificación. Su responsabilidad se limita a
ordenar etapas, ejecutarlas y controlar las condiciones de detención.

## Componentes incorporados

### MetadataApplicationContext

Representa el estado mutable de una ejecución individual.

Contiene:

- solicitud de aplicación;
- identificador de ejecución;
- token de cancelación;
- tiempos de inicio y término;
- resultado de validación;
- resultado de respaldo;
- resultado de escritura;
- resultado final de aplicación;
- resultados auditables por etapa;
- razón de detención;
- mensaje de error.

El contexto queda inmutable después de ser finalizado.

### IMetadataApplicationStage

Define el contrato común de una etapa del pipeline.

Cada etapa declara:

- identidad funcional;
- nombre legible;
- orden de ejecución;
- operación asíncrona sobre el contexto compartido.

### MetadataApplicationStageBase

Centraliza la infraestructura repetitiva de las etapas:

- validación del contexto;
- rechazo de ejecuciones duplicadas;
- comprobación de cancelación;
- medición de tiempos;
- captura de excepciones;
- construcción de resultados auditables;
- registro del resultado en el contexto.

Las etapas concretas sólo deben implementar su lógica específica.

### MetadataApplicationPipelineOptions

Permite configurar el comportamiento del ejecutor:

- detenerse ante fallos bloqueantes;
- detenerse ante cancelaciones;
- detenerse ante etapas omitidas;
- rechazar órdenes duplicados;
- finalizar automáticamente el contexto.

### MetadataApplicationPipelineExecutionResult

Resume la ejecución realizada:

- etapas registradas;
- etapas ejecutadas;
- etapa de detención;
- mensaje de detención;
- presencia de fallos;
- presencia de cancelación;
- ejecución completa o anticipadamente detenida.

### MetadataApplicationPipelineExecutor

Recibe una colección de etapas, valida su configuración, las ordena y
las ejecuta secuencialmente sobre una única instancia del contexto.

El orden se determina por:

1. `ExecutionOrder`;
2. identidad funcional de la etapa.

## Reglas implementadas

- El ejecutor exige al menos una etapa.
- No permite etapas nulas.
- No permite identidades funcionales duplicadas.
- No permite etapas con identidad `None`.
- Todas las etapas deben tener un nombre.
- Puede rechazar órdenes duplicados en modo estricto.
- No ejecuta un contexto ya finalizado.
- Se detiene ante un fallo bloqueante cuando la opción está habilitada.
- Puede finalizar automáticamente un contexto tras una ejecución
  completa y correcta.

## Decisión arquitectónica

El pipeline evolucionará hacia una composición de etapas independientes:

1. validación;
2. respaldo;
3. escritura;
4. verificación;
5. finalización.

Las etapas compartirán un único `MetadataApplicationContext`, mientras
`MetadataApplicationPipelineExecutor` controlará exclusivamente el
orden y el flujo de ejecución.

Esto permitirá incorporar nuevas etapas sin modificar el núcleo del
ejecutor.
