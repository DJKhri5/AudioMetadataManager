# Milestone 13.24

## Adquisición e incrustación de carátulas

## Objetivo

Permitir que una pista obtenga su carátula: descargar la imagen
propuesta por una fuente externa de metadatos (por ejemplo, la
`ArtworkUrl` de un `MetadataCandidate` de Discogs) e incrustarla en el
archivo de audio local mediante TagLibSharp.

A diferencia de Chromaprint y AcoustID, esta operación **escribe** en
el archivo. Por eso exige el mismo principio de seguridad que el resto
del pipeline de aplicación de metadatos: nunca se escribe sin un
respaldo verificado.

## Investigación previa

Antes de implementar se auditó el pipeline de escritura existente
(`Services/Simulation/Application/Writing/**`) para confirmar que no
había una vía ya construida para incrustar imágenes:

- `MetadataCandidate.ArtworkUrl` y `DiscogsSearchCandidate.CoverImageUri`
  ya existían, pero no los consumía nada más allá de un campo de
  consenso legado sin salida real.
- `MetadataFieldChange.NewValue` es siempre `string`; no hay forma de
  transportar datos binarios por ese camino.
- `TagLibFieldMapper` solo admite Artist/Title/Album/Genre; el enum
  `MetadataField` no tiene un valor de carátula.
- El pipeline real (`TagLibMetadataWriterBase`) ya lee
  `tag.Pictures?.Length` antes y después de escribir, pero únicamente
  para detectar pérdida accidental de imágenes existentes — nunca
  asigna `tag.Pictures`.
- No existía código de descarga binaria en todo el proyecto; los
  únicos `HttpClient` existentes (Discogs, AcoustID) son clientes JSON.

Conclusión: no había nada que extender in place. Se construyó una
vertical nueva e independiente, siguiendo el mismo nivel de
granularidad que Chromaprint/AcoustID, en lugar de forzar la carátula
dentro de `MetadataField`/`TagLibFieldMapper`/`MetadataChangeProposal`
(que habría exigido tocar el motor de consenso, el de decisión de
cambios y el mapper de campos escalares).

## Componentes incorporados

Nueva carpeta `Services/Artwork/`, hermana de `MetadataSources` y
`Simulation`.

### Descarga

- `Configuration/ArtworkDownloadOptions.cs`: tamaño máximo (10 MB por
  defecto), tiempo de espera y tipos de contenido admitidos
  (`image/jpeg`, `image/png`).
- `Models/ArtworkDownloadStatus.cs`, `ArtworkDownloadRequest.cs`,
  `ArtworkDownloadResult.cs`.
- `Download/ArtworkDownloader.cs`: descarga vía `HttpClient`,
  rechazando la solicitud antes de leer el cuerpo si
  `Content-Length` ya supera el máximo, y **leyendo en bloques con un
  límite duro** aunque el servidor no informe el tamaño por
  adelantado (protección ante servidores que no declaran
  `Content-Length`).

### Incrustación

- `Models/ArtworkEmbedStatus.cs`, `ArtworkEmbedRequest.cs`,
  `ArtworkEmbedResult.cs`.
- `Embedding/TagLibArtworkEmbedder.cs`: abre el archivo con
  `TagLib.File.Create`, construye un `TagLib.Picture` a partir de los
  bytes descargados y reemplaza (o agrega a) `tag.Pictures`.

  Antes de tocar el archivo, replica exactamente las mismas
  validaciones de seguridad que `TagLibMetadataWriterBase`:

  - el archivo debe existir;
  - debe existir un respaldo verificado (`VerifiedBackupPath`), o se
    rechaza con `MissingBackup`;
  - el respaldo no puede ser el mismo archivo que el original.

### Orquestación

- `Models/TrackArtworkStatus.cs`, `TrackArtworkRequest.cs`,
  `TrackArtworkResult.cs`.
- `TrackArtworkService.cs`: combina `ArtworkDownloader` y
  `TagLibArtworkEmbedder`. Si la descarga falla, nunca intenta
  escribir.

### Diagnostics

`Diagnostics/TrackArtworkDiagnostics.cs`: ejecuta el flujo completo
contra un archivo real y arma un informe. Su documentación deja
explícito que, a diferencia de los diagnósticos de solo lectura de
Chromaprint/AcoustID, esta prueba modifica el archivo indicado y el
llamador debe pasar una copia, no el original.

## Decisión arquitectónica

`TrackArtworkService` no se integró en
`MetadataApplicationPipelineFactory` ni en las etapas existentes
(Validation/Backup/Writing/Verification, órdenes 100-400). Conectarlo
como una etapa real del pipeline requeriría además decidir cómo
transporta un `MetadataApplyRequest` una URL de carátula (dado que
`MetadataFieldChange` es estrictamente string), lo cual es un cambio
de diseño mayor que excede este milestone.

## Verificación

Prueba real de extremo a extremo, no solo compilación:

1. `dotnet build`: 0 advertencias, 0 errores.
2. Prueba de humo en un proyecto de consola temporal en el
   scratchpad de la sesión (con `ProjectReference` al proyecto real).
3. Se copió un archivo real de la biblioteca del usuario
   (`Dusted - Childhood.mp3`) a una carpeta temporal aislada, dos
   veces: una como "copia de trabajo" (la que se modifica) y otra
   como "respaldo verificado".
4. `TrackArtworkService.AcquireAsync` descargó una imagen JPEG real
   (3949 bytes) desde una URL pública de prueba y la incrustó en la
   copia de trabajo: `Success`, `0 -> 1` imagen(es).
5. Se reabrió el archivo modificado con una instancia nueva de
   `TagLib.File` (no el mismo objeto en memoria) y se confirmó de
   forma independiente que contiene 1 imagen — prueba que la
   escritura quedó persistida en disco, no solo en memoria.
6. Se calculó el hash SHA-256 del archivo **original** de la
   biblioteca antes y después de toda la prueba: idéntico. El
   archivo real del usuario nunca fue tocado.
7. Se eliminó la carpeta temporal de prueba al finalizar.
