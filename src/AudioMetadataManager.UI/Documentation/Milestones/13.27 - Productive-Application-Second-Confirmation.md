# 13.27 - Segunda confirmación y aplicación productiva controlada

## Objetivo

Implementar la coordinación segura de una aplicación productiva individual de metadatos mediante dos fases claramente separadas:

1. Preparación y verificación sobre una copia temporal aislada.
2. Segunda confirmación explícita antes de promover la copia verificada hacia el archivo original.

El incremento evita que la interfaz de usuario ejecute directamente operaciones críticas sobre archivos y mantiene la lógica de aislamiento, promoción, respaldo, verificación, reversión y limpieza dentro de servicios especializados.

---

## Alcance implementado

El flujo productivo individual quedó estructurado de la siguiente forma:

```text
Solicitud aprobada
→ preparación aislada
→ pipeline de cinco etapas
→ copia verificada conservada
→ segunda confirmación
→ Approved o Declined
→ promoción opcional
→ limpieza final
```

La preparación inicial no modifica el archivo original.

---

## Modelos agregados

### `MetadataPromotionDecision`

Representa la decisión registrada durante la segunda confirmación.

Estados disponibles:

- `NotRequested`
- `Pending`
- `Approved`
- `Declined`
- `Unavailable`

Una preparación correcta termina inicialmente en `Pending`.

### `MetadataProductiveApplicationResult`

Consolida el resultado completo del flujo productivo individual.

Incluye:

- resultado de la ejecución aislada;
- decisión de promoción;
- resultado de la promoción;
- estado de la limpieza final;
- mensajes auditables;
- error general;
- clasificación del estado final.

Propiedades derivadas principales:

- `VerifiedCopyWasPrepared`
- `PromotionWasDeclined`
- `PromotionWasApproved`
- `PromotionWasSuccessful`
- `PromotionWasSafelyRolledBack`
- `OriginalEndedInSafeState`
- `WasSuccessfullyPromoted`
- `WasSafelyDeclined`
- `EndedInControlledState`

El rechazo voluntario del usuario no se considera un error técnico.

---

## Contrato del coordinador

Se agregó:

```text
IMetadataProductiveApplicationCoordinator
```

El contrato divide el flujo en dos operaciones.

### `PrepareAsync`

Ejecuta el pipeline sobre una copia aislada y conserva el entorno únicamente cuando la copia termina correctamente verificada.

Resultado esperado:

```text
Copia verificada disponible
→ PromotionDecision.Pending
→ archivo original intacto
```

### `CompleteAsync`

Recibe una preparación pendiente y una decisión explícita:

```text
Approved
```

o:

```text
Declined
```

La interfaz queda fuera de la lógica técnica y solamente entrega la decisión obtenida del usuario.

---

## Implementación del coordinador

Se agregó:

```text
MetadataProductiveApplicationCoordinator
```

El coordinador integra:

- `MetadataApplicationIsolatedExecutor`
- `IMetadataApplicationPromotionService`
- `FileIsolationTestHarness`

### Preparación

`PrepareAsync`:

1. valida la solicitud;
2. ejecuta el pipeline sobre una copia temporal;
3. solicita la conservación de una ejecución satisfactoria;
4. comprueba que existe una copia verificada;
5. devuelve una decisión `Pending`.

### Finalización con `Declined`

`CompleteAsync` con decisión `Declined`:

1. registra el rechazo;
2. no entrega el archivo original al servicio de promoción;
3. elimina el entorno aislado;
4. clasifica el resultado como rechazo seguro.

Resultado esperado:

```text
PromotionResult = null
WasSafelyDeclined = true
OriginalEndedInSafeState = true
```

### Finalización con `Approved`

`CompleteAsync` con decisión `Approved`:

1. entrega la copia verificada al servicio de promoción;
2. utiliza el archivo original como destino;
3. crea y verifica un respaldo productivo;
4. ejecuta una sustitución controlada;
5. verifica el destino;
6. ejecuta una reversión automática si la verificación falla;
7. elimina el entorno aislado.

Resultado esperado:

```text
WasSuccessfullyPromoted = true
OriginalEndedInSafeState = true
```

---

## Protección contra doble finalización

Se incorporó una reserva interna de preparaciones finalizadas.

El coordinador identifica cada preparación mediante:

```text
FileIsolationContext.TestDirectoryPath
```

Las preparaciones finalizadas se registran en una colección protegida mediante `lock`.

Esto impide:

```text
Preparación Pending
→ CompleteAsync
→ segunda llamada a CompleteAsync
→ promoción o limpieza repetida
```

Una preparación válida puede finalizarse una sola vez.

---

## Manejo de decisiones inválidas

`CompleteAsync` solamente acepta:

```text
MetadataPromotionDecision.Approved
```

o:

```text
MetadataPromotionDecision.Declined
```

Una decisión inválida:

- produce un resultado auditable con error;
- no ejecuta promoción;
- no reserva la preparación;
- no elimina el entorno aislado;
- permite completar posteriormente la preparación con una decisión válida.

La limpieza final solamente se ejecuta cuando la finalización fue reservada correctamente.

---

## Limpieza final

La limpieza del entorno aislado está protegida mediante:

```text
completionWasReserved
```

El entorno se elimina únicamente después de una finalización válida.

Esto evita que una decisión inválida destruya una copia verificada todavía pendiente de confirmación.

El respaldo productivo creado durante una promoción aprobada permanece independiente del entorno aislado.


## Seguridad alcanzada

El incremento confirma que:

- el archivo original no se modifica durante la preparación;
- ninguna promoción ocurre sin una decisión `Approved`;
- un rechazo explícito termina de manera segura;
- el destino posee un respaldo productivo antes del reemplazo;
- el reemplazo es verificado;
- un fallo posterior puede activar una reversión automática;
- las preparaciones no pueden reutilizarse;
- una decisión inválida no elimina una preparación pendiente;
- los entornos temporales son eliminados de forma controlada;
- las pruebas no modifican archivos reales de la biblioteca.
