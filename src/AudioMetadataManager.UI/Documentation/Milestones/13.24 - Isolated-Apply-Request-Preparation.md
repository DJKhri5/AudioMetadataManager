# Milestone 13.24

## Preparación segura de solicitudes para ejecución aislada

## Objetivo

Preparar la conexión entre el Modo Simulación y el coordinador productivo de aplicación de metadatos, manteniendo protegido el archivo original durante esta fase.

El milestone incorpora el control de disponibilidad del botón de aplicación, una confirmación explícita del usuario, la transformación de solicitudes aprobadas hacia copias temporales aisladas y una mejora de la distribución visual de la ventana principal.

## Alcance

Este milestone incorpora:

* sincronización entre el plan de simulación y el botón productivo;
* habilitación del botón únicamente cuando existen cambios aprobados;
* confirmación explícita antes de una futura ejecución;
* cancelación segura por parte del usuario;
* creación de solicitudes equivalentes destinadas a copias temporales;
* preservación de identificadores, cambios y requisitos;
* pruebas controladas de la fábrica de solicitudes aisladas;
* integración diagnóstica temporal;
* mejora del espacio disponible para el registro de actividad;
* incorporación de un separador ajustable entre detalles y registro.

## Sincronización del plan activo

`MainWindow` centraliza ahora la sustitución del plan mediante:

```csharp
SetCurrentSimulationPlan(
    SimulationPlanViewModel? simulationPlan)
```

Este método:

1. elimina la suscripción del plan anterior;
2. asigna el nuevo plan;
3. registra la escucha de cambios mediante `PropertyChanged`;
4. actualiza la vista de simulación;
5. sincroniza el estado del botón de aplicación.

El plan se limpia cuando:

* se selecciona una biblioteca diferente;
* se inicia un nuevo análisis de biblioteca;
* deja de existir un plan válido para el archivo actual.

## Disponibilidad de la acción productiva

El botón:

```text
Respaldar y aplicar cambios
```

permanece deshabilitado cuando no existe un plan con propuestas aprobadas.

La disponibilidad se calcula mediante:

```csharp
_currentSimulationPlan?.HasApprovedChanges == true
```

Cuando el usuario marca o desmarca propuestas, `MainWindow` recibe la notificación de:

* `HasApprovedChanges`;
* `ApprovedChangeCount`.

De esta manera, el botón se habilita y deshabilita automáticamente sin necesitar un nuevo análisis.

## Confirmación explícita

El evento `ApplyChangesButton_Click` comprueba:

* existencia del plan activo;
* existencia de cambios aprobados;
* cantidad de cambios que se pretenden aplicar.

Antes de continuar, se presenta un cuadro de confirmación que informa:

* cantidad de cambios aprobados;
* nombre del archivo;
* creación obligatoria de un respaldo;
* verificación previa a la escritura.

La opción predeterminada es `No`.

## Cancelación por el usuario

Cuando el usuario selecciona `No`, el registro muestra:

```text
La aplicación de cambios fue cancelada por el usuario.
```

La operación termina sin crear solicitudes de escritura y sin modificar archivos.

## Confirmación controlada

Cuando el usuario selecciona `Sí`, el registro muestra:

```text
Aplicación confirmada para 1 cambio(s) aprobado(s).
```

Durante este milestone la confirmación todavía no ejecuta una escritura productiva sobre el archivo original.

También se registra explícitamente:

```text
La ejecución productiva todavía no está habilitada en este incremento. Ningún archivo fue modificado.
```

## Fábrica de solicitudes aisladas

`MetadataApplyRequestIsolationFactory` construye una nueva instancia de `MetadataApplyRequest` destinada exclusivamente a una copia temporal de trabajo.

La fábrica conserva:

* `RequestId`;
* `PlanId`;
* `CreatedAtUtc`;
* colección de cambios;
* requisito de respaldo;
* requisito de verificación posterior.

La fábrica sustituye únicamente:

* `FilePath`;
* `FileName`.

El nuevo destino corresponde a la copia temporal proporcionada mediante `workingCopyPath`.

## Validaciones de entrada

La fábrica rechaza:

* solicitudes nulas;
* rutas vacías o formadas únicamente por espacios.

La ruta recibida se normaliza mediante:

```csharp
Path.GetFullPath(...)
```

El nombre de archivo se deriva de la ruta aislada mediante:

```csharp
Path.GetFileName(...)
```

## Pruebas controladas

`MetadataApplyRequestIsolationFactoryTestRunner` valida la transformación sin escribir archivos.

Las comprobaciones confirmaron:

* solicitud nula rechazada;
* ruta vacía rechazada;
* identificadores conservados;
* fecha de creación conservada;
* colección de cambios conservada;
* requisitos conservados;
* ruta aislada aplicada correctamente;
* nombre aislado aplicado correctamente.

Resultado general:

```text
Prueba de la fábrica aislada correcta: Sí
```

Resumen obtenido:

```text
La fábrica de solicitudes aisladas superó todas las comprobaciones controladas.
```

## Mejora del diseño de la ventana

La distribución vertical de `MainWindow` fue ajustada para evitar que el registro de actividad quedara reducido a una sola línea.

Los cambios incluyen:

* encabezado más compacto;
* menor tamaño del título;
* menor separación vertical;
* proporciones revisadas para tabla y detalles;
* altura mínima útil para el registro;
* incorporación de un `GridSplitter`.

El usuario puede arrastrar el separador horizontal para distribuir el espacio entre:

```text
Detalles del archivo seleccionado
```

y:

```text
Registro de actividad
```

Los botones inferiores permanecen visibles durante el ajuste.

## Resultado arquitectónico

El flujo preparado queda establecido como:

```text
Plan de simulación
    → Propuestas aprobadas
    → Botón productivo habilitado
    → Confirmación explícita
    → Solicitud técnica original
    → Solicitud destinada a copia aislada
```

Este milestone no ejecuta todavía el coordinador desde el botón productivo.

La fábrica aislada queda preparada para que el siguiente incremento pueda combinar:

```text
FileIsolationTestHarness
    + MetadataApplyRequestIsolationFactory
    + MetadataApplicationCoordinator
```

sin entregar el archivo original al escritor.

## Limitaciones actuales

* La confirmación todavía no invoca el coordinador.
* La copia temporal no se crea desde el botón productivo.
* No se muestra aún un informe final de ejecución aislada.
* No se ofrece aún una opción para conservar o eliminar la copia temporal.
* No existe todavía aplicación directa sobre el archivo original.
* No se procesa todavía más de un plan en una sola operación.
