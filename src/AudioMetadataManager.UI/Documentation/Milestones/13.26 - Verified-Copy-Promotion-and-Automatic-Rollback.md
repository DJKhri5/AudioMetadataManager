# Milestone 13.26

## Conservación, promoción y reversión segura de una copia verificada

## Objetivo

Diseñar y validar la transición técnica desde una ejecución aislada satisfactoria hacia una futura aplicación definitiva sobre el archivo original.

Este milestone incorpora la capacidad de:

* conservar temporalmente una copia de trabajo ya verificada;
* crear un respaldo productivo antes de sustituir un destino;
* promover una copia verificada mediante una operación controlada;
* verificar binariamente el archivo promovido;
* revertir automáticamente el destino cuando la verificación posterior falla;
* conservar evidencia auditable de cada operación;
* probar todos los caminos exclusivamente sobre archivos temporales.

La integración productiva con el archivo original seleccionado por el usuario todavía no está habilitada.

## Punto de partida

Al finalizar el milestone 13.25, el sistema podía:

```text
Plan aprobado
    → solicitud de aplicación
    → copia temporal aislada
    → pipeline productivo de cinco etapas
    → verificación
    → limpieza automática
```

Ese comportamiento protegía completamente el archivo original, pero eliminaba siempre la copia modificada después de validarla.

Para implementar una futura segunda confirmación era necesario permitir:

```text
Ejecución aislada correcta
    → conservar copia verificada
    → decidir posteriormente
        → promoverla
        → o descartarla
```

## Opciones de ejecución aislada

Se incorporó:

```csharp
MetadataApplicationIsolatedExecutionOptions
```

Este modelo controla el ciclo de vida del entorno temporal mediante:

```text
CleanupAfterExecution
PreserveVerifiedWorkingCopy
CleanupAfterFailure
```

La configuración predeterminada es:

```csharp
MetadataApplicationIsolatedExecutionOptions
    .SafeCleanupDefault
```

Este modo conserva el comportamiento previamente validado:

```text
Ejecución terminada
    → eliminar entorno temporal
```

También se incorporó:

```csharp
MetadataApplicationIsolatedExecutionOptions
    .PreserveSuccessfulExecution
```

Este modo permite:

```text
Ejecución correcta
    → conservar copia verificada
    → posponer limpieza
```

Cuando la ejecución falla, el entorno sigue eliminándose automáticamente.

## Servicio de promoción controlada

Se incorporó:

```csharp
MetadataApplicationPromotionService
```

El servicio ejecuta el siguiente flujo:

```text
1. Validar las rutas
2. Verificar que origen y destino sean diferentes
3. Verificar que las extensiones coincidan
4. Calcular el hash inicial del destino
5. Calcular el hash de la copia verificada
6. Crear un respaldo productivo
7. Verificar el respaldo productivo
8. Crear un archivo de preparación junto al destino
9. Verificar el archivo de preparación
10. Sustituir el destino
11. Verificar el destino promovido
12. Revertir automáticamente cuando la verificación falla
13. Eliminar archivos auxiliares
14. Devolver un resultado auditable
```

## Respaldo productivo

Antes de cualquier sustitución, el servicio crea:

```text
Carpeta del destino
└── AudioMetadataManager_Backup
    └── yyyy-MM-dd
        └── identificador único
            └── archivo original
```

El respaldo debe cumplir:

```text
Archivo existente
+ hash igual al destino anterior
```

Si no puede crearse o verificarse, la sustitución no comienza.

## Archivo de preparación

La copia verificada no sustituye directamente el destino.

Primero se crea un archivo auxiliar dentro de la misma carpeta:

```text
.<nombre>.<identificador>.promotion.tmp
```

Después se verifica que dicho archivo coincida exactamente con la copia verificada.

Solo entonces se ejecuta:

```csharp
File.Replace(...)
```

Esto permite realizar la sustitución dentro del mismo sistema de archivos y reducir el riesgo de una operación incompleta entre ubicaciones diferentes.

## Verificación posterior

Después de sustituir el destino se calcula nuevamente su hash.

La promoción se considera correcta únicamente cuando:

```text
Hash del destino final
    =
Hash de la copia verificada
```

Si los hashes no coinciden, la promoción se rechaza y se inicia la reversión.

## Reversión automática

Cuando la sustitución ya fue ejecutada pero la verificación posterior falla, el servicio:

```text
1. detecta el fallo
2. conserva el error original
3. inicia una reversión
4. copia el respaldo a un archivo auxiliar
5. verifica el archivo auxiliar
6. sustituye el destino con el respaldo
7. calcula nuevamente el hash
8. confirma que el destino coincide con su estado inicial
```

El archivo auxiliar de reversión utiliza:

```text
.<nombre>.<identificador>.rollback.tmp
```

## Simulación de fallo posterior

La opción:

```csharp
SimulatePostReplacementVerificationFailure
```

permite rechazar deliberadamente la verificación después de que la sustitución temporal haya ocurrido.

La simulación:

* no corrompe bytes;
* no elimina el respaldo;
* no modifica el archivo original de la biblioteca;
* no depende de errores externos;
* activa exactamente el camino de reversión real.

## Limitaciones actuales

* El botón principal todavía no promueve cambios al archivo original.
* No existe todavía una segunda confirmación de usuario.
* El respaldo productivo aún no tiene una ubicación configurable.
* No existe todavía una política de retención de respaldos.
* No se ha implementado restauración manual desde la interfaz.
* No se procesan lotes de archivos.
* La promoción todavía se encuentra dentro del espacio de pruebas de la aplicación.
* Las pruebas temporales continúan integradas en Diagnóstico técnico.
* No existe todavía un estado visual que represente una copia pendiente de promoción.

## Próximo paso previsto

El siguiente milestone deberá convertir los componentes validados en un flujo de aplicación individual productivo.

Ese flujo deberá incorporar:

```text
1. ejecución aislada
2. conservación de copia verificada
3. presentación de un resumen al usuario
4. segunda confirmación explícita
5. respaldo productivo persistente
6. promoción al archivo original
7. verificación posterior
8. mensaje final auditable
9. limpieza del entorno aislado
```

Antes de habilitarlo será necesario definir:

* texto exacto de la segunda confirmación;
* ubicación definitiva de los respaldos;
* tratamiento de cancelaciones;
* comportamiento cuando el archivo cambió externamente;
* conservación o limpieza de la copia después de una promoción;
* actualización del plan y de la interfaz;
* procedimiento de restauración manual.
