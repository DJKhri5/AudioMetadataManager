# Milestone 13.28

## Proveedor de metadatos Spotify

## Objetivo

Reemplazar el *stub* de Spotify (`IsAvailable => false`) por un
proveedor real, siguiendo la misma organización en capas que ya usan
Discogs y AcoustID.

## Por qué Spotify no necesita que el usuario inicie sesión

La API de Spotify ofrece dos flujos de autenticación. El de
"Authorization Code" exige que un usuario final inicie sesión y
autorice la app — útil para acceder a datos privados (listas de
reproducción, biblioteca guardada). Para lo que necesita esta
aplicación (buscar en el catálogo público por artista/título), alcanza
con el flujo **"Client Credentials"**: la app se autentica a sí misma
con un Client ID y un Client Secret, sin ningún usuario de por medio.
Es tan simple de configurar como el token personal de Discogs, sólo
que en vez de un valor estático hay que pedir un token, que expira y
se renueva automáticamente.

## Componentes incorporados

Misma organización en capas que Discogs/AcoustID, bajo
`Providers/Spotify/`.

### Configuration

- `SpotifyOptions`: direcciones de la API y del punto de emisión de
  tokens, Client ID, Client Secret, resultados por página, tiempo de
  espera.
- `SpotifyCredentialStore`: guarda Client ID y Client Secret por
  separado en el Administrador de credenciales de Windows, mismo
  patrón que `DiscogsTokenStore`.
- `SpotifyOptionsFactory`.

### Api

- **`SpotifyAuthClient`**: pieza nueva sin equivalente en Discogs.
  Solicita un token vía `POST /api/token` con autenticación HTTP
  Basic (`Client ID:Client Secret` en Base64) y `grant_type=client_credentials`.
  Conserva el token en memoria y lo reutiliza mientras falten más de
  30 segundos para que expire (margen de seguridad para no usar un
  token que venza a mitad de una solicitud); lo renueva
  automáticamente cuando corresponde. Protegido con `SemaphoreSlim`
  para evitar solicitar dos tokens en paralelo si dos búsquedas
  llegan al mismo tiempo.
- `SpotifyApiRequestBuilder`: arma la URL de `/v1/search` con
  `q=artist:X track:Y`, `type=track`, `limit`.
- `SpotifyApiClient`: obtiene el token vigente mediante
  `SpotifyAuthClient` antes de cada búsqueda y lo adjunta como
  `Bearer` en la solicitud.

### Dtos / Mapping / Models / Execution

Mismo patrón que Discogs: DTOs que reflejan el JSON de Spotify
(`tracks.items[]` con `artists[]`, `album.images[]`, `external_urls`),
`SpotifySearchResponseParser`, `SpotifySearchCandidateMapper` (elige
la imagen de portada de mayor resolución disponible, une artistas con
"&nbsp;,&nbsp;", extrae el año desde `release_date`),
`SpotifySearchExecutor`.

### SpotifyMetadataProvider

Punto de entrada público: valida configuración, datos mínimos de
búsqueda y presencia de credenciales antes de delegar, igual que
`DiscogsMetadataProvider`.

### SpotifyMetadataSource (adaptador `IMetadataSource`)

Reemplaza el *stub* existente en `Providers/SpotifyMetadataSource.cs`.
`IsAvailable` ahora depende de la configuración real
(`Options.IsValid && Options.HasCredentials`), no de una constante
`false`. Se registró en `MetadataSourceFactory.CreateDefault`, que
ahora acepta un parámetro opcional `SpotifyOptions?` (mismo patrón que
ya existía para `DiscogsOptions?`).

### Diagnostics

`SpotifySearchDiagnostics`, para verificación manual.

## Verificación

**No se probó contra la API real de Spotify**: todavía no hay Client
ID ni Client Secret configurados (el usuario está por registrar la app
en el panel de desarrolladores de Spotify). Se verificó todo lo que no
requiere credenciales reales, con un proyecto de consola en el
scratchpad:

1. `SpotifyApiRequestBuilder.BuildSearchUri` construye correctamente
   la URL de búsqueda (`type=track`, `q=artist:... track:...`,
   `limit`).
2. Sin credenciales configuradas: `SpotifyMetadataProvider.IsAvailable`
   es `false` y `SearchAsync` devuelve `AuthenticationFailed` con un
   mensaje claro, sin lanzar excepciones.
3. `SpotifyAuthClient.GetAccessTokenAsync` sin credenciales devuelve
   `InvalidConfiguration` de forma controlada.
4. Se parseó una respuesta JSON de ejemplo con la forma real de la API
   de Spotify (dos pistas, una utilizable y una sin artista ni
   título): el parser y el mapeador de candidatos funcionaron
   correctamente — descartaron la pista inutilizable, unieron
   artistas, calcularon la duración desde `duration_ms`, y eligieron
   la imagen de portada de **mayor** resolución entre varias
   disponibles.
5. El mapeo al contrato común (`MetadataSearchResult`/`MetadataCandidate`)
   extrajo correctamente el año desde `release_date` (`"2004-06-15"`
   → `2004`).

`dotnet build`: 0 advertencias, 0 errores (SDK 8.0.423 / entorno con
SDK 10.0.302 tras instalar Visual Studio, ambos compilan el proyecto
`net8.0-windows` sin problema).
