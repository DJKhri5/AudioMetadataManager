# 13.28 - Integración productiva con segunda confirmación en la interfaz

## Objetivo

Integrar el flujo productivo de aplicación de metadatos con la interfaz principal de Audio Metadata Manager.

El botón:

```text
Respaldar y aplicar cambios
```

deja de limitarse a ejecutar el pipeline sobre una copia temporal y pasa a coordinar el flujo completo de aplicación productiva en dos fases:

```text
Preparación aislada
→ segunda confirmación explícita
→ aprobación o rechazo
→ promoción o cancelación segura
→ limpieza final
```

La integración mantiene protegido el archivo original durante toda la preparación y exige una segunda confirmación antes de realizar cualquier sustitución productiva.

---

## Situación anterior

Antes de este incremento, `ApplyChangesButton_Click` ejecutaba directamente:

```text
MetadataApplicationIsolatedExecutor.ExecuteAsync
```

El comportamiento anterior permitía:

- crear una copia temporal;
- ejecutar el pipeline de cinco etapas;
- escribir metadatos sobre la copia;
- verificar los valores escritos;
- conservar intacto el archivo original;
- mostrar un resultado de ejecución aislada.

Sin embargo, el flujo terminaba después de la preparación.

La interfaz todavía no utilizaba:

```text
MetadataProductiveApplicationCoordinator
```

y no existía una segunda confirmación visual conectada con:

```text
CompleteAsync
```

Por lo tanto, la copia verificada no podía ser promovida desde el flujo real del botón hacia el archivo original.

---

## Flujo productivo integrado

El botón productivo quedó conectado con el siguiente flujo:

```text
Plan de simulación aprobado
→ creación de MetadataApplyRequest
→ PrepareAsync
→ ejecución aislada del pipeline
→ copia verificada conservada
→ segunda confirmación visual
→ Approved o Declined
→ CompleteAsync
→ promoción o cancelación segura
→ resultado mostrado al usuario
```

El archivo original no se modifica durante `PrepareAsync`.

La promoción solo se ejecuta cuando el usuario selecciona explícitamente:

```text
Sí
```

en la segunda confirmación.

---

## Coordinador productivo registrado en la interfaz

Se agregó a `MainWindow` el campo:

```text
MetadataProductiveApplicationCoordinator
```

La instancia se inicializa en el constructor de la ventana principal.

El ejecutor aislado anterior se conserva porque continúa siendo utilizado por otros flujos de diagnóstico y pruebas internas.

La nueva dependencia productiva se utiliza específicamente para coordinar:

```text
PrepareAsync
CompleteAsync
```

desde `ApplyChangesButton_Click`.

---

## Preparación productiva

La ejecución directa de:

```text
MetadataApplicationIsolatedExecutor.ExecuteAsync
```

fue reemplazada por:

```text
MetadataProductiveApplicationCoordinator.PrepareAsync
```

`PrepareAsync` recibe la solicitud construida a partir del plan de simulación aprobado.

Durante esta fase se realizan las siguientes operaciones:

1. validación de la solicitud;
2. creación de un entorno temporal aislado;
3. creación de una copia de trabajo;
4. creación de un respaldo inicial;
5. ejecución del pipeline de aplicación;
6. escritura de los cambios aprobados;
7. verificación posterior a la escritura;
8. comprobación de integridad;
9. conservación de la copia verificada;
10. mantenimiento del archivo original sin cambios.

El resultado productivo contiene internamente:

```text
MetadataApplicationIsolatedExecutionResult
```

La interfaz extrae este resultado mediante:

```text
productiveResult.IsolatedExecutionResult
```

Esto permite conservar el registro existente de:

- entorno aislado preparado;
- pipeline completado;
- archivo original intacto;
- copia temporal modificada;
- respaldo inicial preservado;
- etapas ejecutadas;
- campos aplicados;
- resumen del pipeline.

---

## Manejo de preparación incompleta

Si `PrepareAsync` no produce un resultado aislado disponible, la interfaz:

- registra el error;
- muestra el resumen productivo;
- informa que no fue posible preparar una copia verificable;
- confirma que el archivo original permaneció intacto;
- termina el flujo sin solicitar una aprobación.

Mensaje utilizado:

```text
Preparación productiva incompleta
```

No se llama a `CompleteAsync` cuando no existe una copia verificada disponible.

---

## Conservación del entorno verificado

La interfaz dejó de interpretar la ausencia de limpieza inmediata como un fallo.

Durante una preparación productiva correcta:

```text
EnvironmentWasPreserved = true
```

Esto significa que:

- el entorno aislado sigue existiendo;
- la copia verificada permanece disponible;
- el respaldo inicial permanece disponible;
- la limpieza automática fue pospuesta;
- el flujo espera una segunda decisión del usuario.

El registro muestra:

```text
Entorno verificado conservado: Sí
Copia disponible para segunda confirmación: Sí
```

La conservación es intencional y forma parte del flujo productivo seguro.

---

## Segunda confirmación visual

Cuando la copia verificada está disponible, la interfaz muestra una segunda confirmación mediante:

```text
MessageBoxButton.YesNo
```

El mensaje informa que:

- la copia temporal fue preparada;
- la copia fue verificada;
- el archivo original todavía permanece intacto;
- seleccionar `Sí` aplicará los cambios;
- seleccionar `No` cancelará la promoción.

Título de la confirmación:

```text
Segunda confirmación requerida
```

La opción predeterminada es:

```text
No
```

Esto evita que una pulsación accidental confirme la modificación productiva.

---

## Conversión de la respuesta visual

La respuesta del usuario se transforma en:

```text
MetadataPromotionDecision.Approved
```

cuando selecciona:

```text
Sí
```

o en:

```text
MetadataPromotionDecision.Declined
```

cuando selecciona:

```text
No
```

La decisión queda registrada antes de llamar a `CompleteAsync`.

Mensajes auditables:

```text
El usuario aprobó la promoción productiva.
```

o:

```text
El usuario rechazó la promoción productiva.
```

---

## Finalización productiva

Después de obtener la decisión, la interfaz llama:

```text
MetadataProductiveApplicationCoordinator.CompleteAsync
```

La operación recibe:

- el resultado de la preparación;
- la decisión de promoción.

El coordinador procesa uno de dos caminos:

```text
Pending → Approved
```

o:

```text
Pending → Declined
```

El resultado se almacena como:

```text
MetadataProductiveApplicationResult
```

---

## Camino Declined

Cuando el usuario selecciona `No`, el coordinador:

1. registra la decisión `Declined`;
2. evita ejecutar el servicio de promoción;
3. no sustituye el archivo original;
4. elimina la copia temporal;
5. elimina el entorno aislado;
6. conserva el archivo original intacto;
7. finaliza en un estado seguro.

La interfaz registra:

```text
Promoción aprobada: No
Promoción rechazada: Sí
Promoción completada: No
Rechazo seguro: Sí
Archivo original en estado seguro: Sí
Estado final controlado: Sí
```

Mensaje mostrado al usuario:

```text
Aplicación cancelada
```

Contenido principal:

```text
La promoción fue cancelada.

El archivo original permaneció intacto y el entorno temporal fue eliminado de forma segura.
```

---

## Validación del camino Declined

La prueba funcional del camino `Declined` confirmó:

- la copia temporal fue preparada;
- el pipeline terminó correctamente;
- el archivo original permaneció intacto;
- la copia temporal recibió el cambio aprobado;
- la copia quedó disponible para segunda confirmación;
- el usuario rechazó la promoción;
- el servicio productivo no sustituyó el original;
- el entorno aislado fue eliminado;
- el resultado final quedó en estado controlado.

Resultado:

```text
Rechazo seguro: Sí
Archivo original en estado seguro: Sí
Estado final controlado: Sí
```

La prueba terminó sin modificar los metadatos del archivo original.

---

## Camino Approved

Cuando el usuario selecciona `Sí`, el coordinador:

1. registra la decisión `Approved`;
2. valida las rutas de entrada;
3. valida la existencia de la copia verificada;
4. identifica el archivo original como destino;
5. crea un respaldo productivo;
6. verifica el respaldo productivo;
7. crea un archivo de preparación junto al destino;
8. verifica el archivo de preparación;
9. ejecuta la sustitución controlada;
10. compara el archivo promovido con la copia verificada;
11. confirma la persistencia del cambio;
12. elimina el entorno aislado;
13. devuelve un resultado productivo satisfactorio.

La promoción no ocurre directamente desde la interfaz.

Toda la sustitución permanece encapsulada dentro del servicio productivo.

---

## Registro del camino Approved

La interfaz registra:

```text
Promoción aprobada: Sí
Promoción rechazada: No
Promoción completada: Sí
Rechazo seguro: No
Archivo original en estado seguro: Sí
Estado final controlado: Sí
```

También se registran los mensajes internos del coordinador:

```text
Se inició la preparación productiva sobre una copia temporal aislada.
La copia verificada fue preparada y conservada correctamente.
El usuario aprobó la promoción de la copia verificada hacia el archivo original.
Las rutas y los archivos de entrada fueron validados.
El respaldo productivo fue creado.
El respaldo productivo fue verificado.
El archivo de preparación fue creado y verificado junto al destino.
La sustitución controlada fue ejecutada.
El archivo promovido coincide con la copia verificada.
La promoción productiva terminó correctamente.
El entorno aislado fue eliminado correctamente.
```

---

## Mensaje de aplicación correcta

Cuando:

```text
WasSuccessfullyPromoted = true
```

la interfaz muestra:

```text
Cambios aplicados
```

Contenido principal:

```text
Los cambios fueron aplicados correctamente.

Se creó y verificó un respaldo antes de modificar el archivo original.

La escritura final también fue verificada.
```

Este mensaje solo se presenta cuando la promoción y la verificación final terminaron correctamente.

---

## Resultado incompleto

Cuando el resultado no corresponde a:

```text
WasSuccessfullyPromoted
```

ni a:

```text
WasSafelyDeclined
```

la interfaz muestra:

```text
Finalización productiva incompleta
```

El mensaje informa que:

- el flujo no terminó correctamente;
- el sistema intentó conservar el archivo en un estado seguro;
- el usuario debe revisar el Registro de actividad.

Los errores técnicos quedan registrados mediante:

```text
completedResult.ErrorMessage
```

junto con:

```text
completedResult.Summary
```

---

Formato general:

```text

- mensajes del coordinador

```

Esto permite reconstruir:

- qué decisión tomó el usuario;
- si se ejecutó una promoción;
- si se creó el respaldo;
- si se verificó el destino;
- si el original terminó seguro;
- si el entorno temporal fue eliminado;
- si el proceso terminó de forma controlada.

---

## Respaldo productivo

Antes de sustituir el archivo original, el servicio productivo crea un respaldo independiente.

El respaldo:

- se crea antes de la sustitución;
- se verifica mediante integridad binaria;
- no depende del respaldo inicial de la copia temporal;
- puede utilizarse para reversión;
- queda separado del entorno aislado de preparación.

La existencia de dos respaldos responde a responsabilidades diferentes:

```text
Respaldo inicial
→ protege el estado inicial de la copia aislada
```

```text
Respaldo productivo
→ protege el archivo original antes de la sustitución
```

---

## Reversión automática disponible

Aunque la prueba real del botón terminó correctamente y no necesitó una reversión, el servicio utilizado conserva la capacidad de:

1. detectar un fallo después de la sustitución;
2. iniciar la reversión;
3. restaurar el archivo desde el respaldo productivo;
4. verificar el archivo restaurado;
5. informar que el destino terminó en un estado seguro.

La interfaz recibe esta evidencia mediante:

```text
MetadataProductiveApplicationResult
```

y puede mostrar un resultado controlado incluso cuando la promoción no se completa.

---

## Seguridad de la interfaz

Durante la operación, el botón productivo permanece deshabilitado mediante el bloque existente de control de ejecución.

La interfaz evita:

- iniciar dos aplicaciones simultáneas;
- repetir accidentalmente la preparación;
- promover una copia sin confirmación;
- utilizar una preparación más de una vez;
- limpiar una preparación antes de una decisión válida;
- ejecutar la promoción después de un rechazo;
- ocultar errores de finalización.

El botón se vuelve a habilitar dentro del bloque `finally`.

- el usuario confirma la segunda advertencia;
- la promoción supera todas las verificaciones.

La modificación productiva permanece explícita y separada del análisis normal.

## Resultado del incremento

El botón productivo quedó conectado con el flujo real de dos fases:

```text
PrepareAsync
→ segunda confirmación
→ CompleteAsync
```

Los dos caminos fueron validados:

```text
Pending → Declined
```

y:

```text
Pending → Approved
```

El camino `Declined` conserva el archivo original sin cambios.

El camino `Approved` crea un respaldo, promueve la copia verificada y confirma la persistencia del cambio.

El Milestone 13.28 deja funcional la aplicación productiva individual desde la interfaz principal con:

- preparación aislada;
- segunda confirmación obligatoria;
- respaldo productivo;
- promoción verificada;
- cancelación segura;
- reversión disponible;
- limpieza controlada;
- registro auditable;
- verificación posterior del valor aplicado.
